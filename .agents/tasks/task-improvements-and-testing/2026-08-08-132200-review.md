# UI enhancements and Playwright E2E test suite for Instagram Poster Generator

This change adds four user-facing features (favicon, loading spinner, theme selector, copy-to-clipboard) and a Playwright E2E test suite with GitHub Actions CI. The implementation is vanilla JS/CSS with no build tooling, keeping the project's static-site philosophy intact. The tests run against a local `serve` instance and cover the core happy paths.

Watch for: The spinner overlay uses `position: fixed`, covering the entire viewport rather than scoping to the poster area (confirmed). The `copyToClipboard` and `downloadPoster` functions hardcode `backgroundColor: '#ffffff'`, so dark/gradient posters export with a white background (confirmed). Three of four new features (spinner, themes, clipboard) have no test coverage.

**Verdict**: NEEDS_CHANGES

## High-level view

The spinner overlay is placed inside `.poster-wrapper` in the DOM but styled with `position: fixed` and full viewport dimensions — a mismatch between structural intent (scoped to poster) and visual behavior (covers the page).

Theme switching applies CSS classes to `#poster` and overrides colors via descendant selectors. Both `downloadPoster()` and `copyToClipboard()` pass `backgroundColor: '#ffffff'` to html2canvas, defeating the dark and gradient themes on export.

The Playwright suite validates page load, URL validation, form-to-poster data flow, QR code generation, and button presence. It does not test the spinner, the theme selector, or the copy-to-clipboard feature. Several tests rely on `waitForTimeout` instead of deterministic wait conditions.

<details>
<summary>Issues (4)</summary>

1. **Spinner covers viewport, not poster area** — The `.spinner-overlay` uses `position: fixed` with full viewport dimensions. Change to `position: absolute` and add `position: relative` to `.poster-wrapper` so the spinner scopes to the poster section.
2. **Theme ignored on export** — Both `downloadPoster()` and `copyToClipboard()` pass `backgroundColor: '#ffffff'` to html2canvas. For dark/gradient themes, omit the `backgroundColor` option or derive it from the active theme class so the exported image matches what the user sees.
3. **No tests for spinner, theme, or clipboard** — Three of four new features lack test coverage. Add at least: theme class applied on select change, spinner visibility around generate action, copy button state change on click.
4. **`waitForTimeout` usage in tests is fragile** — Several tests use hard-coded `waitForTimeout(500)` or `waitForTimeout(1000)` instead of waiting for a specific condition. Prefer `waitForSelector`, `waitForFunction`, or Playwright's auto-retrying assertions.

</details>

## Spinner overlay positioning

The spinner HTML lives inside `.poster-wrapper`:

```html
<div class="poster-wrapper">
    ...
    <div id="spinner-overlay" class="spinner-overlay hidden">
        <div class="spinner"></div>
    </div>
    ...
</div>
```

But the CSS positions it as a fixed full-screen overlay:

```css
.spinner-overlay {
    position: fixed;
    top: 0;
    left: 0;
    width: 100%;
    height: 100%;
    ...
}
```

Either move to `position: absolute` with a `position: relative` on the parent, or relocate the element to `<body>` level if full-screen blocking is intended. The current placement inside `.poster-wrapper` suggests the intent is a scoped overlay.

## Theme export mismatch

Both export paths share the same html2canvas options:

```javascript
const canvas = await html2canvas(poster, {
    scale: 2,
    useCORS: true,
    allowTaint: true,
    backgroundColor: '#ffffff',  // <-- always white
    logging: false
});
```

When `theme-dark` is active the poster background is `#1a1a1a`. When `theme-gradient` is active it's a CSS gradient. The hardcoded white `backgroundColor` forces html2canvas to paint a white backdrop, overriding the visual theme. For solid-color themes, read the computed background from the poster element. For gradient themes, set `backgroundColor: null` and let html2canvas use the element's own rendering.

## Test coverage gaps

The seven tests cover page load/title, invalid URL alert, valid URL non-alert, manual form updates poster DOM, QR code canvas rendered, download button presence, and copy button presence.

Missing: spinner visibility during `generatePoster()`, theme class application when the select changes, copy-to-clipboard behavior (at minimum that the button text transitions to "Copying..." and back). The two button-existence tests confirm static HTML is rendered — they exercise none of the new JS logic.

## `waitForTimeout` fragility

```javascript
await page.waitForTimeout(500);
expect(dialogMessage).toContain('valid Instagram post URL');
```

The dialog handler captures the message synchronously when the dialog fires, so the test could use `await page.waitForEvent('dialog')` or assert after the click promise resolves, instead of hoping 500ms is enough. Under CI load this will eventually race.

The QR code test waits 500ms for render. A `waitForSelector('#qr-code canvas')` would be deterministic.
