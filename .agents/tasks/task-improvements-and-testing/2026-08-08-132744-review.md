# UI enhancements, Playwright E2E suite, and CI pipeline for Instagram Poster Generator (v2)

This change adds a favicon, loading spinner scoped to the poster container, a light/dark/gradient theme selector with theme-aware export, a copy-to-clipboard button, 10 Playwright E2E tests, and a GitHub Actions CI pipeline. All four issues from the v1 review — spinner positioning, theme-aware export, missing test coverage, and fragile `waitForTimeout` — have been addressed. The implementation stays faithful to the vanilla HTML/CSS/JS architecture.

Watch for: The `displayUsername` variable is injected via `innerHTML` without escaping in the caption render path, creating a DOM-based XSS vector (confirmed). The `copyToClipboard` function re-enables the button in the `finally` block even on success, creating a brief window where the button shows "Copied!" but is already clickable again (confirmed, minor).

**Verdict**: NEEDS_CHANGES

## High-level view

The username field value is used raw in an `innerHTML` assignment on line 194 of `script.js`. While the caption and comment text pass through `escapeHtml()`, the username does not — allowing script injection from the form input.

The copy-to-clipboard button's disabled state and text label are managed in separate control flows: `finally` re-enables the button immediately, while a `setTimeout` resets the label after 2 seconds. This leaves a window where rapid clicks re-trigger the full html2canvas render.

<summary>Issues (2)</summary>

1. **Unescaped username in innerHTML (XSS)** — `displayUsername` is interpolated directly into `innerHTML` at line 194 of `script.js`: `` `<strong>${displayUsername}</strong> ${escapeHtml(caption)}` ``. A value like `<img src=x onerror=alert(1)>` in the username field triggers script execution. Wrap it with `escapeHtml(displayUsername)`.
2. **Copy button re-enabled before "Copied!" timeout expires** — The `finally` block sets `copyBtn.disabled = false` immediately after the success path sets the text to "Copied!". The user can click the button again during the 2-second feedback window. Move `copyBtn.disabled = false` into the `setTimeout` callback or after the timeout resolves.

## Unescaped username in caption innerHTML

Line 194 of `script.js`:

```javascript
document.getElementById('poster-caption').innerHTML = `<strong>${displayUsername}</strong> ${escapeHtml(caption)}`;
```

`displayUsername` is derived directly from the `#username` input field (line 145). The `escapeHtml` function is applied to `caption` but not to `displayUsername`. Any value containing angle brackets will be parsed as HTML. The poster-username span on line 146 uses `textContent` (safe), but the caption paragraph uses `innerHTML` (unsafe) — an inconsistency within the same function.

## Copy button state during feedback window

The success path in `copyToClipboard()`:

```javascript
copyBtn.textContent = 'Copied!';
setTimeout(() => {
    copyBtn.textContent = 'Copy to Clipboard';
}, 2000);
```

The `finally` block:

```javascript
} finally {
    copyBtn.disabled = false;
}
```

Because `finally` runs synchronously after the `try` block completes, the button becomes enabled while still showing "Copied!" — for 2 seconds the user can re-trigger the clipboard write, causing a duplicate canvas render. Moving `disabled = false` into the timeout callback (and also into the `catch` path) would make the button state internally consistent.
